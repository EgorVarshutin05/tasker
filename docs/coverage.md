# Покрытие и интерпретация результатов

## Операторы

`make coverage` инструментирует только три прикладных пакета: service, repository, handler. Модель без поведения, точка сборки зависимостей, web/embed.go, тестовые утилиты и инструменты отчета в знаменатель не входят, как задано планом.

Блок profile содержит число операторов и счетчик исполнения. Для повторяющегося положения блока в нескольких тестовых бинарных файлах счетчики складываются, число операторов учитывается один раз. Формула: `100 * sum(statements where count>0) / sum(statements)`. Скрипт `tools/check_coverage.py` создает machine-readable JSON и завершает работу кодом 1, если общий результат ниже 85% или service ниже 90%.

## Исходы решений

`make branches` инструментирует временную копию трех файлов приложения через go/ast. У if и for с явным условием учитываются true/false; у switch — каждый case и default, в том числе неявный исход без выбранного case. Значение логического выражения вычисляется один раз, исходная последовательность short-circuit сохраняется внутри выражения. Ветви тестов и диагностических инструментов исключаются.

Range рассматривается как механизм итерации, его нулевой/ненулевой объем в метрику не включен. MC/DC, отдельные операнды `&&`/`||` и все пути не измеряются. Это явная граница модели покрытия решений, а не полное покрытие потока управления.

`reports/branches/manifest.json` содержит исходный файл, строку, функцию, текст условия и перечисление исходов. `events/` содержит фактические события разных тестовых процессов. `summary.json` связывает события и реестр, перечисляет пропущенные исходы. В production-сборку диагностический пакет не попадает.

Порог — 80% суммарно и 100% в service. Общий процент не заменяет ручной анализ пропущенных исходов. Например, искусственное получение ошибки LastInsertId от настоящего SQLite-драйвера может потребовать иного класса тестового драйвера. Ни эта метрика, ни процент операторов не доказывают отсутствие дефектов.

## Наборы и журналы

Все наборы U01–U05, I01–I05, A01–A05, S01–S05 обязательны. I06–I08 добавлены для границ HTTP, отказов хранения и параллельного доступа. Логи Go содержат полные имена `TestU03IDBoundaries/Complete/0` и другие имена наборов. Число запусков берется из фактических записей, а не из количества top-level тестовых функций.

Факты конкретной проверки архива находятся в verification. После изменения исходников нужен новый прогон; копирование прежних процентов в отчет о другой версии не допускается.
